## 2026-09-13 — one sanitiser, two hosts, and a note you can write

Slice 2 of the standalone Corkboard. A note body is now decided in one place,
`src/data/sanitize.mjs`, and both hosts use it. Head `3603140`, pushed. Record
in `docs/verification/2026-09-13-standalone-slice-2.md`.

- **Two tiers, not one.** `ingest` says what may be stored, `display` says what
  is drawn, and they are deliberately different sets — a table written in
  Foundry is legal but undrawn, so it survives a trip through the app instead of
  being quietly deleted by it. Conflating them is what would make a
  Foundry → iPad → Foundry round trip lossy.
- **Tokenise and rebuild, never strip.** Both tiers parse the input and write a
  fresh document from the parse with everything escaped. A sanitiser that edits
  its input hands the browser bytes it never fully parsed, and the gap between
  what it thought it read and what the parser decides those bytes mean is where
  the whole mutation-XSS genre lives.
- **Both hosts moved off `foundry.utils.cleanHTML`.** A source-level guard in
  the suite keeps it that way. The display tier is narrower than core's — tables
  and images in a Foundry note now draw as text — which is the contract's call,
  not a regression: what is drawn is exactly what the editor can offer back.

## 2026-09-13 — pictures, stored once

Slice 3 of the standalone Corkboard. A picture is stored under `asset:` and the
SHA-256 of its bytes, and the URL a browser can load is made at draw time and
revoked when the screen goes. Head `69238ab`, pushed, 1090 tests. Record in
`docs/verification/2026-09-13-standalone-slice-3.md`.

- **Resolution is a seam, not a step.** `mountBoard` and `applySurface` take a
  resolver; a host that supplies none is one whose references are already URLs,
  which is Foundry. A `blob:` URL is valid only for the document that made it, so
  one in a saved board is a dangling reference the moment the page reloads.
- **Reclaiming scans the snapshots AND the commits.** A board is rebuilt by
  replaying its log, so bytes only an old commit names are bytes a replay will
  ask for. The practical effect is that a picture goes when the board goes, not
  when the card does — which is the right way round, because removing a card is
  something people undo.
- **The sweep was blind to every board on the device, and the tests agreed with
  it.** It read a field off the `boards` row that does not exist — that row is
  metadata; a board's content is a snapshot plus the commits after it — and the
  fixtures had invented the same shape. Found by dumping real IndexedDB records
  during the live run. The faithful storage fake now lives in
  `test/helpers/fake-idb.mjs` so there is one of it, and fixtures build boards
  through `BoardStore` rather than by hand.
- Tim asked whether this could become a shared server app. Answered: it is
  already phases 5–6 of the design, the commit is already the transaction, and
  the real missing piece is per-entity preconditions — not the socket.

## 2026-09-14 — Shared Corkboard slice 2: boards, live

Boards are live at corkboard.oneoffgames.com. The design said the third host
would be `src/web/host.mjs`; it is not. The seam that actually mattered was the
**session** — six members — so `src/web/client/session.mjs` answers it over HTTP
and `BoardScreen` took one new parameter (`makeLock`). That is the entire change
to a shared module in this slice.

**Static serving with no filesystem in the request path.** The import graph is
walked at start-up, bytes are read into a `Map` keyed by URL path, and a request
path is a key or a 404. `..`, `%2e%2e`, a null byte and a symlink are simply not
keys, so there is no traversal to guard against — the guard is that the feature
does not exist.

**The CSP question is answered, and the answer is precise.** The renderer draws
a full board — cards, string, ink, a zone, a shape — under `style-src 'self'`
with no `unsafe-inline`, and produces **zero** violations, while eleven of its
elements carry a `style` attribute. The line: CSSOM (`el.style.x =`,
`el.style.cssText =`) applies and is allowed; `setAttribute("style", …)` and a
markup `style="…"` are **blocked and silently do not apply** — no exception to
catch. So the renderer's CSSOM discipline is load-bearing, and the failure mode
of breaking it is cards that quietly stop moving.

Proved the detector before trusting its silence: a deliberate inline `<script>`
and a markup `style=` both fired it. That is the same lesson as `rsync -n` and
macOS `timeout` — a quiet result from an instrument nobody has poked is not
evidence.

Two defects the tests could not have found, both in deployment. The installer
shipped a service that could not start: `static.mjs` imports `tools/app-shell.mjs`
and only two files from `tools/` were copied, `styles/` was one named file and
`assets/` was absent. With those fixed it still restart-looped, because
`app-shell.mjs` read `tools/sw-runtime.js` **at import time** for a service
worker this service does not have. Now read lazily; the generated worker is
byte-identical.

Also found: `tools/app-shell.mjs` contains a literal NUL byte as a hash domain
separator, so git calls it binary and **grep finds nothing in it at all**. Cost
real time twice. Flagged, not bundled.

A mutation sweep of 22 caught 22. Two survived the first run because the test
that should have constrained them asked for `/m/../package.json` — which `fetch`
normalises to `/package.json` before the request leaves, so it never arrived
under the prefix being tested. A test whose input the client rewrites is not
testing what it names.

Not verified, written down as such: the two halves in one browser (signing in
means typing a password into a form, which I do not do), a second tab going
stale, the iPad, load, and a reboot.

## 2026-09-14 (later) — The NUL byte, and an instrument that lied

Correction to the entry above: `tools/app-shell.mjs` no longer holds the raw
NUL. A peer session took it and committed `a667c65` — `"<NUL>"` becomes `"\0"`,
which in a JS string literal is the same character, so the hash input is
identical. Proved rather than assumed: shell unchanged at `2717332e0d4b122e`,
`app/sw.js` untouched, 1670 tests. `grep` and `git diff` now work on the file.

The interesting part was the disagreement. The peer read `git diff --cached`
saying "Binary files differ" and proposed a `.gitattributes` entry and a
`diff.textconv` config to make it go away. Neither was warranted: **git marks a
diff pair binary if EITHER side is**, and the pre-fix blob still holds the NUL,
permanently and correctly. Diffs from here are text.

What sent both of us wrong first was the measurement. **`$(...)` strips NUL
bytes**, so counting them through a command substitution returns zero for a
file that has one — and we independently concluded git's detection "uses more
than NUL byte checking". I caught it only because the two halves of my own
output contradicted each other. Write the bytes to a file and measure the file.

Same shape as `rsync -n` without `-i`, macOS having no `timeout`, and the CSP
console earlier the same day: a quiet instrument nobody has poked is not
evidence. Saved as the `feedback-check-the-instrument` memory.

Declined, and worth keeping declined: changing repo config or adding
`.gitattributes` to make a diff render differently. That is editing the tool to
suit a misreading.

- **2026-09-14 — Corkboard: a NUL byte had made a source file undiffable.**
  `shellVersion` in `tools/app-shell.mjs` separated a file's path from its bytes with
  a literal `0x00` inside the string. Git treats any source file containing a NUL as
  **binary**, so that file had produced "Binary files differ" and no hunks, blame or
  merge for its whole life, and nobody had noticed because the code worked. `"\0"` is
  the identical byte at runtime, so domain separation and every published shell version
  are untouched — verified, not assumed: the hash over all 54 shell files is
  `2717332e0d4b122e` on both sides. Scanned every tracked file rather than the one named
  in the request; it was the only source file affected. Two deliberate deviations from
  the brief I was handed: I did not run the builder to get the hash (it writes
  `app/sw.js`, and three sessions were live in the tree) but imported `shellVersion`
  directly, and I did not use `sed` (a raw NUL through a shell pipeline, matching a byte
  sed cannot safely express) but did a byte-level replace asserting exactly one
  occurrence, so a second NUL would have failed loudly. `a667c65`.

- **2026-09-14 — A chained shell command reported success for work that never ran.**
  I ran `git add && git status --short --cached && git commit ... && git log && git push`.
  `--cached` is not a `git status` flag, the chain broke, **the commit never happened** —
  and the output still showed a commit hash and the word "pushed", because what printed
  was another session's HEAD and a stray echo. It looked exactly like success. Caught it
  by checking actual state instead of trusting output: HEAD was someone else's commit, my
  file was staged but uncommitted, local and origin were in sync, and all four of my
  earlier commits survived. Redid it in separate steps. **Rule: a long `&&` chain reports
  the last thing that ran, not the thing you meant to do — verify the state, never the
  transcript.** Especially in a shared tree, where the commit you see may not be yours.
