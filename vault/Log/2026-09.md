- **The multi-tab lock is `navigator.locks`, not a `BroadcastChannel` election.**
  Contracts §5 amended in place. A BroadcastChannel post from `pagehide` is
  queued as a task and the document is destroyed before it runs, so closing the
  tab holding a board left the other read-only for good, and nothing in an
  announce-and-listen protocol can hear a tab that died without speaking. The
  browser owns its lock and releases it when the tab goes. Every decision in §5
  stands; only the mechanism moved.
- **A change is shown only after it is stored.** Showing first is faster by one
  IndexedDB round trip and lies whenever the write fails — which on a device
  whose storage can be evicted is the expensive option.
- **Writes are declared as operation lists rather than handed-out transactions**,
  which makes "the board and its commit land together" structural and sidesteps
  a transaction held across an `await` being closed by the browser.

## 2026-09-13 — one sanitiser, two hosts, and a note you can write

Slice 2 of the standalone Corkboard. A note body is now decided in one place,
`src/data/sanitize.mjs`, and both hosts use it. Head `3603140`, pushed. Record
in `docs/verification/2026-09-13-standalone-slice-2.md`.

- **Two tiers, not one.** `ingest` says what may be stored, `display` says what
  is drawn, and they are deliberately different sets — a table written in
  Foundry is legal but undrawn, so it survives a trip through the app instead of
  being quietly deleted by it. Conflating them is what would make a
  Foundry → iPad → Foundry round trip lossy.
- **Tokenise and rebuild, never strip.** Both tiers parse the input and write a
  fresh document from the parse with everything escaped. A sanitiser that edits
  its input hands the browser bytes it never fully parsed, and the gap between
  what it thought it read and what the parser decides those bytes mean is where
  the whole mutation-XSS genre lives.
- **Both hosts moved off `foundry.utils.cleanHTML`.** A source-level guard in
  the suite keeps it that way. The display tier is narrower than core's — tables
  and images in a Foundry note now draw as text — which is the contract's call,
  not a regression: what is drawn is exactly what the editor can offer back.
- **The Foundry save path is not verified live.** One line in `sheet.mjs`, no
  unit tests on that file and never has been, and no deploy this slice. It is
  owed a run inside Foundry.
- Six defects found live, all fixed, including one left behind by slice 1:
  `TAP_SLOP` was referenced and never declared, so tapping bare cork to clear
  the selection threw inside a `pointerup` listener and had never once worked.
  The mutation sweep — not hand-testing — found two of the others, both ways of
  smuggling a CSS `url()` past the check.
- The lesson that keeps repeating: a decision inline in a DOM handler is a

- **2026-09-13 — Corkboard: a tap with the pen leaves no mark.** Defect 6 from the
  standalone slice-1 live run, left alone at the time because it needed a decision
  rather than a patch. A press with no travel stored a stroke of one point, and a
  `<polyline>` with one point has no subpath: it painted nothing, measured 0x0, and
  its `.cb-stroke-hit` companion inherited the same empty box, so the mark could be
  counted but never seen, selected or rubbed out. Decided **refuse**, not draw. A
  tap is how you reach a mark with the pen still in your hand — the app selects on
  the press, the module opens a mark's menu on a right-click — so a tap that painted
  would stamp ink on the very thing you were reaching for; and the highlighter's
  chisel tip is a `butt` linecap, which paints nothing for a zero-length subpath, so
  repeating the point would have left a highlighter tap exactly as invisible as it
  already was. The rule is one predicate, `isStroke`, asked by both `addStroke` and
  the renderer. Two things worth keeping: the comment arguing "a dot still deserves
  to exist" sat on a branch that could never run — `thinStroke` keeps its first point
  regardless — so the dot was never a decision anyone took; and refusing does not
  retract the one-point strokes already on saved boards, which `transfer.mjs` copies
  between worlds wholesale, so the renderer now declines to draw them instead of
  emitting a polyline that lies about being there. 12 of 12 mutants caught, 968 → 976
  tests. Committed `ab20565` alongside a concurrent session's in-flight asset work,
  staged hunk by hunk so none of theirs went in.


## 2026-09-13 — pictures, stored once

Slice 3 of the standalone Corkboard. A picture is stored under `asset:` and the
SHA-256 of its bytes, and the URL a browser can load is made at draw time and
revoked when the screen goes. Head `69238ab`, pushed, 1090 tests. Record in
`docs/verification/2026-09-13-standalone-slice-3.md`.

- **Resolution is a seam, not a step.** `mountBoard` and `applySurface` take a
  resolver; a host that supplies none is one whose references are already URLs,
  which is Foundry. A `blob:` URL is valid only for the document that made it, so
  one in a saved board is a dangling reference the moment the page reloads.
- **Reclaiming scans the snapshots AND the commits.** A board is rebuilt by
  replaying its log, so bytes only an old commit names are bytes a replay will
  ask for. The practical effect is that a picture goes when the board goes, not
  when the card does — which is the right way round, because removing a card is
  something people undo.
- **The sweep was blind to every board on the device, and the tests agreed with
  it.** It read a field off the `boards` row that does not exist — that row is
  metadata; a board's content is a snapshot plus the commits after it — and the
  fixtures had invented the same shape. Found by dumping real IndexedDB records
  during the live run. The faithful storage fake now lives in
  `test/helpers/fake-idb.mjs` so there is one of it, and fixtures build boards
  through `BoardStore` rather than by hand.
- Tim asked whether this could become a shared server app. Answered: it is
  already phases 5–6 of the design, the commit is already the transaction, and
  the real missing piece is per-entity preconditions — not the socket.
