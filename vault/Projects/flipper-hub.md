# Flipper Hub

**What it is** — A native SwiftUI macOS app that runs Tim's Flipper Zero ("Haluor",
fw 1.3.4) and its ESP32-S2 Marauder WiFi board over one USB cable, so he drives the
device from the Mac instead of the 128×64 screen and five buttons. Layout B: the
live Flipper screen pinned on the left of every tab, nine tool tabs on the right —
Library, IR, WiFi, Sub-GHz, Backup, Macros, Payloads, Remotes, Device.

**Where it lives** — `~/flipperhub`, branch `main`, **no git remote yet** (local
checkout only). Build with `bash build.sh` (SwiftPM, no Xcode — Command Line Tools
only) → ad-hoc-signed `FlipperHub.app`. One dependency: swift-protobuf. Design and
plan in `docs/superpowers/`.

**Current state** — Built and merged to `main` on 2026-11-03 (subagent-driven, 17
tasks + a post-review fix wave). **115 tests pass, app builds.** Tests are **Swift
Testing**, not XCTest (XCTest is absent under CLT); run them with `./test.sh`, which
wraps `swift test` with the `-plugin-path` flag because plain `swift test` flakes on
cold builds. Everything is desk-verified; nothing has been run against the hardware
with Tim yet.

**Key decisions**
- One `PortArbiter` actor owns the single USB link and serialises RPC / CLI / Bridge;
  nothing opens a serial port directly. Protobuf RPC vendored from
  flipperzero-protobuf @ 0.25, regenerated by `scripts/gen-proto.sh`.
- **WiFi is "Option A"**: an on-device spike proved the board has no Mac-facing
  serial on this hardware, so the WiFi tab drives the Flipper's own Marauder app
  (loader + input events) and reads the SD logs/pcaps over the storage RPC rather
  than talking to the board. `BridgeController`/`BoardTransport` are retained but
  unused (marked dead-code, kept for a possible future direct-serial board).
- Two independent authorised-switches (WiFi offensive features; BadUSB payloads),
  both disarmed on every launch, no persistence, explicit confirm to arm.
- Quit-teardown best-effort stops a running Marauder op and disconnects.
  `MarauderController.bestEffortStop` **must stay `nonisolated`** or the detached
  teardown deadlocks on the blocked main actor (that was the final review's one
  Critical).

**Next steps** — On-device pass WITH TIM (the only things left; none are code
defects, they are un-testable without the hardware): tune the Marauder on-screen
menu step constants + log-filename matching; verify IR learn→tx hex/endianness (raw
`.ir` sends, which Tim's real `Remote.ir` uses, are unaffected); confirm Sub-GHz and
IR CLI output formats; decide the status-strip board presence/version (left blank
rather than faked); optional busy-cue for long storage reads. Also open: whether to
create a private remote (slaguru666) and push.
