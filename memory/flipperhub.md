Flipper Hub — native SwiftUI macOS app at `~/flipperhub` (git repo, branch `main`, remote slaguru666/flipperhub (private)). Drives the owner's Flipper Zero ("Haluor", fw 1.3.4) and its ESP32-S2 Marauder WiFi board over one USB link. Layout B: live Flipper screen pinned left, nine tabs right (Library, IR, WiFi, Sub-GHz, Backup, Macros, Payloads, Remotes, Device). Built via SwiftPM + `build.sh` (no Xcode, CLT only) → ad-hoc-signed FlipperHub.app; one dep (swift-protobuf). Tests are **Swift Testing** (not XCTest — absent under CLT); run with `./test.sh` (wraps `swift test` with `-Xswiftc -plugin-path .../host/plugins/testing` because plain `swift test` flakes on cold builds). 115 tests pass.

Key architecture: single `PortArbiter` actor serialises RPC/CLI/Bridge on the one USB link (nothing opens a port directly). Flipper protobuf RPC vendored from flipperdevices/flipperzero-protobuf @ tag 0.25, regenerated by `scripts/gen-proto.sh`. Two independent `AuthorisedGate`s (WiFi offensive + Payloads/BadUSB), fresh-disarmed every launch, no persistence, explicit confirm to arm. Quit-teardown (`AppDelegate.applicationWillTerminate`) best-effort stops a running Marauder op + disconnects; `MarauderController.bestEffortStop` is `nonisolated` — it MUST stay nonisolated or the detached teardown deadlocks on the blocked main actor.

**WiFi is Option A** (on-device spike proved the board has no Mac-facing serial): the tab drives the Flipper's own `esp32_wifi_marauder.fap` via loader + input events and reads SD logs/pcaps (`/ext/apps_data/marauder/logs|pcaps`) over StorageClient. `BridgeController`/`BoardTransport` retained but unused (marked dead-code; kept for a future direct-serial board).

Built subagent-driven (17 tasks + fix wave), finished 2026-11-03. Design/plan in `docs/superpowers/`.

**Still needs on-device verification (no code defect — un-testable without the hardware):** Marauder on-screen menu step constants + log-filename matching; IR learn→tx hex/endianness ([[feedback-...]] T9-A — raw .ir sends unaffected); Sub-GHz/IR CLI output formats; status-strip board presence/version (left blank, not faked); busy-cue for long storage reads. Store names: Macros/Remotes are JSON-content-derived; Payloads are filename-derived (a case-only rename keeps data but not visible case on case-insensitive APFS).
